# Doorstep website

Static, bilingual (EN at `/`, PL at `/pl/`) website for Doorstep, a housing search service in Warsaw.
Plain HTML, one hand-written CSS file and one progressive-enhancement JS file. It is generated by a small
Python script from two copy files. There is no framework and no bundler, so you can host it anywhere,
including GitHub Pages.

```
site/              publish-ready output (generated, do not edit by hand)
src/content/       en.yml, pl.yml: all copy, same keys in both
src/templates/     Jinja2 layout, partials, components, one template per page
src/static/        style.css, site.js, fonts, favicons, GSAP (copied into site/ as is)
build.py           the generator; CONFIG block at the very top
CHECKLIST.md       generated on every build: everything to FILL IN or CONFIRM, with pages
tests/             Playwright + axe tests, link checker, screenshots, REPORT.md
.github/workflows/ GitHub Pages deployment
```

## Build

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt          # jinja2, pyyaml: nothing else at build time
python build.py                          # builds site/ and CHECKLIST.md
python build.py --zip                    # builds and writes doorstep-website.zip
python build.py --strict                 # fails while required FILL IN items are empty or the copy lint warns
python build.py --base-path /doorstep/   # build for a sub-path (GitHub project page)
python build.py --no-highlights --out /tmp/preview   # preview without placeholder highlights
```

Preview locally with `cd site && python -m http.server 8000`, then open http://localhost:8000.

The build stops on an unknown token, a page with zero or two `<h1>`, or `en.yml` and `pl.yml` drifting apart.
It warns about titles over 60 characters, descriptions over 155, banned words, all-caps words and `!!!`.

## Edit

**Facts (fees, NIP, email, WhatsApp…)** live only in `CONFIG` at the top of `build.py`.
- A FILL IN item is a plain string. Leave it `""` until you have the fact, and the site shows a yellow, dashed **FILL IN** mark.
- A CONFIRM item is `{"value": …, "source": …, "confirmed": False}`. It shows its value with a blue, dotted **confirm** tag. Set `confirmed: True` once the team has decided.
- `SHOW_PLACEHOLDER_HIGHLIGHTS = False` hides every mark. Confirm values render as plain text, and sentences that depend on an empty FILL IN item drop out.
- `PRIMARY_LANG = "pl"` swaps the roots: Polish at `/`, English at `/en/`.
- `BASE_PATH` is `"/"` for a custom domain or `user.github.io`, and `"/repo-name/"` for a project page. The GitHub workflow sets it for you.
- `USE_GSAP = False` removes the animations and the GSAP file.

**Copy** lives in `src/content/en.yml` and `pl.yml`, with one top-level key per page and `common` for shared parts.
Inside a string:

| Token | Meaning |
|---|---|
| `[[fill:key]]` | a missing fact from CONFIG |
| `[[confirm:key]]` | a value to confirm, from CONFIG |
| `[[url:page_id]]`, `[[url:page_id#anchor]]` | a link to that page in the current language |
| `[[pl:czynsz]]` | marks a Polish word with `lang="pl"` on English pages |
| `{? … ?}` | an optional sentence, dropped when its FILL IN is empty and highlights are off |

The tone rules from B01 §7 are linted at build time: no superlatives, no "users/clients/customers",
no all-caps words, no `!!!`. On people pages Polish uses *ty*; on university and landlord pages it uses *Państwo / Pan / Pani*.

**Pages** are registered in `PAGES` in `build.py` (id, template, EN slug, PL slug, B01 persona, bottom bar).
Every template marks its sections with the JTBD line or pain point they answer, e.g. `{# L2, pain: fake offers #}`.

**Photos.** Put a real JPEG in `src/static/assets/img/` with `.webp` and `.avif` siblings of the same name, then set
`viewing_photo` or `team_<name>_photo` to its path, e.g. `assets/img/mila.jpg`. Only use photos of real viewings and the real team, with their consent.
**Testimonials.** There is a commented-out `testimonials` macro in `components.html`. Use it only for real, consented quotes.

## Deploy on GitHub Pages

1. Create a repository and push this folder (`git init && git add . && git commit -m "Doorstep site" && git push`).
2. In the repo: **Settings → Pages → Source: GitHub Actions**.
3. Every push to `main` runs `.github/workflows/deploy.yml`, which builds with the right base path and publishes `site/`.
4. Optional repository **variables** (Settings → Secrets and variables → Actions → Variables) override CONFIG without editing code:
   `DOORSTEP_SITE_URL`, `DOORSTEP_FORM_ENDPOINT`, `DOORSTEP_GTM_ID`, `DOORSTEP_GA4_ID`, and any other `DOORSTEP_<KEY>`.
5. Custom domain: add it under Settings → Pages, then set `site_url` (or `DOORSTEP_SITE_URL`) to `https://your-domain`.

Until `site_url` is set, every page is `noindex` and `robots.txt` disallows crawling, so a half-finished site stays out of Google.
Any other static host works too. Upload `site/` as it is; `404.html` and clean folder URLs need no configuration.

## Forms

All five forms (search brief, book a call, proposal request, partnership enquiry, contact) `POST` to `form_endpoint`
with a hidden `form_id`. Any static-form service that accepts `multipart/form-data` and replies with JSON to
`Accept: application/json` works, such as Formspree, Basin or Getform, or your own endpoint. Hidden fields: `form_id`, `page`, `lang`,
`persona`, `utm_source`, `utm_medium`, `utm_campaign`, `referrer`, `fill_ms`, plus the honeypot `website`, which should be empty.
Spam protection is the honeypot plus a minimum fill time of 3 seconds; there is no CAPTCHA.
With JavaScript off, the form posts directly. Configure the service's redirect to `/thanks/?form=<form_id>`
(or `/pl/dziekujemy/?form=…`).

## Measurement

GTM (`gtm_id`) or GA4 (`ga4_id`), whichever is filled; GTM wins if both are. Consent Mode v2 defaults everything to
`denied`, and no Google script loads until the visitor accepts. The banner stores the choice in `localStorage`
(`doorstep_consent`, with a date), and "Cookie settings" in the footer reopens it.

Data-layer events (snake_case parameters, never form contents): `door_click`, `cta_click`, `whatsapp_click`,
`email_click`, `phone_click`, `booking_click`, `form_start`, `form_error`, `generate_lead` (`form_id`, `persona`, `lang`),
`lang_switch`, `faq_open`, `guide_read`, `map_load`, `share_copy`.

In GA4, mark **`generate_lead`**, **`whatsapp_click`** and **`booking_click`** as key events
(Admin → Events → Mark as key event; with GTM, create GA4 event tags for these data-layer events first).
Register `persona` and `form_id` as custom dimensions so leads can be reported per B01 persona
(lena, katrin, marco, agnieszka, piotr). That is how progress on outcomes 1 and 2 shows up.

## Security

External links use `rel="noopener"`, there are no inline event handlers, and forms post over HTTPS only.
Suggested Content-Security-Policy for the host. GitHub Pages cannot set headers, so there it can only go in a `<meta>` tag in `base.html`:

```
default-src 'self';
script-src 'self' 'sha256-IGaFX+b5V7IqJhmXdrl4T+JbOgpi4PePGSAasrGBdpc=' https://www.googletagmanager.com;
connect-src 'self' https://*.google-analytics.com https://*.analytics.google.com https://www.googletagmanager.com <your form endpoint origin>;
img-src 'self' data: https://*.google-analytics.com https://www.googletagmanager.com;
frame-src https://www.google.com;
style-src 'self';
font-src 'self';
form-action 'self' <your form endpoint origin>;
base-uri 'self'; object-src 'none'
```

The hash covers the one-line inline script that swaps `no-js` for `js`. If you change that script (`INLINE_JS` in
`build.py`), recompute the hash. The JSON-LD blocks are data, not script, and are not affected.

## Test

```bash
pip install -r tests/requirements.txt && python -m playwright install chromium
python tests/run_tests.py          # about 5 minutes; --quick skips screenshots
```

It builds four variants: normal, no highlights, analytics and form wired to test values, and served under `/doorstep/`.
It serves each locally and checks links and anchors, the language switch, the sitemap, axe-core on every page at
two viewports, a keyboard-only journey, focus not hidden behind the sticky bars, the menu, the disclosure, FAQ, copy-link, the consent banner
(verified by network interception), the map facade, form validation and submission, UTM capture, overflow at five widths,
tap targets, Polish diacritics in all three fonts, the copy lint and CHECKLIST consistency.
Results go to `tests/results.md`, screenshots to `tests/screenshots/`, and the narrative to `tests/REPORT.md`.
